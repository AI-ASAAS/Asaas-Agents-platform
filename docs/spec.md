# وثيقة توصيف مشروع منصة وكلاء أساس
**ASAAS Agents Platform**

**الجهة المطوّرة:** أساس للذكاء الاصطناعي – ASAAS AI  
**نوع المشروع:** منصة ويب لاستعراض وتجربة وكلاء الذكاء الاصطناعي  
**اللغة الأساسية:** العربية (RTL) مع إمكانية دعم الإنجليزية مستقبلًا  
**مصدر الوكلاء:** وكلاء يتم تطويرهم واعتمادهم داخليًا بواسطة فريق أساس  
**التكاملات الأساسية:** GitHub – AI Model Providers APIs – Agent Runtime

---

## 1. فكرة المشروع

**وكلاء أساس (ASAAS Agents)** هي منصة إلكترونية تابعة لشركة أساس للذكاء الاصطناعي، تهدف إلى توفير مكتبة منظمة ومتجددة من وكلاء الذكاء الاصطناعي (AI Agents) الذين يقوم فريق أساس بتصميمهم وبرمجتهم واختبارهم.

تتيح المنصة للزوار استكشاف الوكلاء المتاحين، والتعرف على وظائفهم وإمكانياتهم، مع توفير خيارين أساسيين لكل وكيل:

1. **تجربة الوكيل مباشرة (Live Demo):** تشغيل الوكيل والتفاعل معه من خلال واجهة بسيطة باستخدام مفتاح API يملكه المستخدم.
2. **الوصول إلى GitHub:** الانتقال إلى المستودع البرمجي الخاص بالوكيل للاطلاع على الكود المصدري والتوثيق وطريقة تشغيله، وفق صلاحيات المستودع.

تعمل المنصة باعتبارها معرضًا تفاعليًا لمنتجات ووكلاء شركة أساس، وليست بيئة تطوير أو بناء وكلاء للمستخدمين.

## 2. آلية تطوير الوكلاء وإضافتهم للمنصة

**جميع الوكلاء المعروضين يتم بناؤهم وإدارتهم بواسطة فريق أساس، ولا يمكن للمستخدم العادي إنشاء وكيل أو إضافته إلى المنصة.**

تمر عملية توفير وكيل جديد بالمراحل التالية:

**المرحلة الأولى – بناء الوكيل**

يقوم فريق أساس بتطوير وكيل ذكاء اصطناعي لتنفيذ وظيفة أو معالجة مشكلة محددة، مثل خدمة العملاء أو تحليل البيانات أو الأتمتة أو البرمجة.

**المرحلة الثانية – الاختبار والتحقق**

يختبر الفريق الوكيل للتأكد من سلامة تشغيله، وصحة استجاباته، وتوافقه مع المزودين والنماذج التي يدعمها، ومعالجة الأخطاء المحتملة.

**المرحلة الثالثة – النشر على GitHub**

بعد التأكد من جاهزية الوكيل، يتم رفع مشروعه إلى مستودع GitHub مع توفير الكود والتوثيق وتعليمات التشغيل والمتطلبات اللازمة.

**المرحلة الرابعة – ضم الوكيل إلى منصة وكلاء أساس**

يقوم مسؤول المنصة بإضافة الوكيل من خلال نظام الإدارة الداخلي، وربط مستودع GitHub الخاص به، وتحديد بياناته وطريقة تشغيل تجربته المباشرة والنماذج المدعومة.

**المرحلة الخامسة – إتاحته للمستخدمين**

يظهر الوكيل في مكتبة المنصة ليتمكن الزائر من الاطلاع عليه وتجربته أو الانتقال إلى مستودعه البرمجي.

تتم عملية إضافة الوكلاء برمجيًا ومن خلال الإدارة الداخلية، دون إظهار أي أدوات لبناء الوكلاء أو نشرهم في الواجهة العامة للمستخدم.

---

## 3. الواجهة العامة للمستخدم

تعتمد المنصة على واجهة عربية احترافية وبسيطة، تتوافق مع الهوية البصرية لشركة أساس.

### 3.1 الصفحة الرئيسية

تحتوي الصفحة الرئيسية على:

- شعار واسم منصة «وكلاء أساس».
- عنوان تعريفي يوضح فكرة المنصة.
- شريط بحث للوصول إلى الوكلاء بالاسم أو الوظيفة.
- تصنيفات الوكلاء حسب مجال الاستخدام.
- بطاقات الوكلاء المتاحة.
- قسم الوكلاء المميزين أو الأكثر تجربة.
- إحصائيات عامة مختصرة، مثل عدد الوكلاء والتجارب، عند توفر بيانات فعلية.

### 3.2 بطاقات الوكلاء

يُعرض كل وكيل ضمن بطاقة مستقلة تحتوي على:

- اسم الوكيل وأيقونته.
- وصف مختصر لوظيفته.
- التصنيف الخاص به.
- حالة جاهزيته للتجربة.
- زر **«تجربة مباشرة»**.
- زر **«GitHub»**.

لا تتضمن البطاقات خيارات بناء الوكيل أو تعديله أو إدارته.

### 3.3 صفحة تفاصيل الوكيل

عند اختيار أحد الوكلاء، تظهر صفحة خاصة تتضمن:

- اسم الوكيل ووصفًا تفصيليًا لإمكانياته.
- الاستخدامات والوظائف التي يدعمها.
- واجهة التجربة المباشرة.
- قسم ربط مفتاح API الخاص بالمستخدم.
- اختيار النموذج المستخدم للتجربة.
- رابط مستودع GitHub.
- معلومات إضافية مختصرة عن الوكيل.

---

## 4. نظام تجربة الوكلاء مباشرة (Live Agent Playground)

تُعد التجربة المباشرة من أهم وظائف المنصة، حيث يمكن للمستخدم اختبار أداء الوكيل قبل تنزيل مشروعه أو تشغيله بنفسه.

تختلف واجهة التجربة بحسب طبيعة الوكيل، فقد تكون محادثة تفاعلية، أو رفع ملف وتحليله، أو إدخال بيانات وتشغيل مهمة معينة.

**المبدأ الأساسي: تجربة الوكلاء تتم باستخدام API الخاص بالمستخدم، وليس باستخدام مفتاح API تابع لشركة أساس.**

### 4.1 ربط API الخاص بالمستخدم

توفر المنصة واجهة إعداد بسيطة تتضمن:

1. اختيار مزود الذكاء الاصطناعي.
2. إدخال مفتاح API الخاص بالمستخدم.
3. التحقق من صلاحية المفتاح وإمكانية الاتصال.
4. جلب النماذج المتاحة للمفتاح من المزود، عندما يدعم المزود ذلك.
5. اختيار أحد النماذج المتوافقة مع الوكيل.
6. بدء التجربة مباشرة.

من المزودين المستهدف دعمهم بحسب توافقهم التقني:

- Google AI Studio (Gemini API).
- OpenAI.
- Anthropic.
- OpenRouter.
- مزودون آخرون يمكن إضافتهم مستقبلًا.

### 4.2 مرونة اختيار المزود والنموذج

يجب ألا تكون المنصة مرتبطة بمزود ذكاء اصطناعي واحد أو بمجموعة ثابتة من النماذج.

فعند اختيار المستخدم مزودًا مثل Google AI Studio، يعرض النظام النماذج المتاحة عبر مفتاحه والمتوافقة مع الوكيل المختار.

وعند التبديل إلى OpenRouter أو OpenAI، تتغير قائمة النماذج وفق المزود والمفتاح المستخدم.

**ملاحظة مهمة:** ليس بالضرورة أن يدعم كل وكيل جميع المزودين والنماذج. لذلك تحدد المنصة خيارات التشغيل المتوافقة فعليًا مع كل وكيل، بدل السماح بخيارات قد تفشل أثناء الاستخدام.

### 4.3 تجربة الوكيل

بعد اختيار النموذج، تظهر واجهة التفاعل الخاصة بالوكيل.

يمكن للمستخدم إرسال الرسائل أو تقديم المدخلات المطلوبة، ومشاهدة النتائج مباشرة.

تعرض الواجهة حالات التشغيل والانتظار والأخطاء بصورة واضحة وبسيطة، دون الحاجة إلى إعدادات تقنية معقدة.

---

## 5. مراقبة استهلاك API

توفر المنصة مراقبة مبسطة لاستهلاك API أثناء تجربة الوكلاء، بحيث تساعد المستخدم على معرفة حجم الاستخدام دون تحويل التجربة إلى لوحة تحكم تقنية معقدة.

يمكن عرض المعلومات التالية:

- عدد الطلبات المنفذة خلال جلسة التجربة.
- عدد التوكنز المستهلكة، إذا أعاد المزود هذه المعلومات.
- التكلفة التقديرية للجلسة عند توفر بيانات التسعير المناسبة.
- حالة الاتصال بالمزود.
- النموذج المستخدم حاليًا.

يُفضّل عرض هذه المعلومات في قسم صغير قابل للتوسيع بعنوان **«استهلاك التجربة»**، بحيث لا تشتت المستخدم عن الوظيفة الأساسية للمنصة.

ولا تتحمل شركة أساس تكلفة استدعاءات نماذج الذكاء الاصطناعي التي ينفذها المستخدم بمفتاحه الخاص؛ وتُحتسب الرسوم، إن وجدت، وفق حسابه لدى مزود الخدمة.

---

## 6. التكامل مع GitHub

يرتبط كل وكيل بمستودع GitHub خاص به.

عند النقر على زر GitHub، ينتقل المستخدم إلى المستودع المرتبط بالوكيل، حيث يمكنه الاطلاع على:

- الكود المصدري.
- ملف README والتوثيق.
- متطلبات التشغيل والتثبيت.
- الإصدارات والتحديثات المتاحة.
- طريقة الإعداد والتشغيل محليًا عند دعم ذلك.

تعتمد إمكانية الوصول إلى الكود على كون المستودع عامًا أو على امتلاك المستخدم صلاحية الوصول إليه.

**ولا يعني وجود الوكيل على GitHub إمكانية تجربته مباشرة بشكل تلقائي.** فالتجربة الحية تحتاج أيضًا إلى بيئة تشغيل أو نقطة اتصال فعلية للوكيل، يتم تجهيزها وربطها من قِبل فريق أساس.

---

## 7. نظام إدارة المنصة

ستتضمن المنصة لاحقًا لوحة إدارة مستقلة ومحمية مخصصة لفريق أساس.

تُستخدم هذه اللوحة في إدارة الوكلاء وإضافتهم وربط مستودعاتهم وتحديث بياناتهم والتحكم في إتاحتها للمستخدمين.

**لا تدخل تفاصيل تصميم لوحة الإدارة ضمن التوصيف الحالي**، وسيتم تحديد وظائفها وصلاحياتها وآلية عملها في مرحلة مستقلة.

لن تظهر أدوات الإدارة أو إضافة الوكلاء أو تعديلهم للزائر العادي.

---

## 8. الأمان والخصوصية

نظرًا لاعتماد المنصة على مفاتيح API الخاصة بالمستخدمين، يجب الالتزام بالمتطلبات التالية:

- التعامل مع مفاتيح API بصورة آمنة وعدم إظهارها للآخرين.
- عدم تسجيل المفاتيح في السجلات أو روابط الصفحات.
- استخدام اتصال HTTPS.
- عدم تخزين المفاتيح بشكل دائم افتراضيًا، والاكتفاء باستخدامها خلال الجلسة وفق آلية آمنة.
- عدم إرسال المفاتيح إلى خدمات غير موثوقة.
- عزل جلسات المستخدمين ومنع وصول أحدهم إلى بيانات اتصال الآخر.
- تقييد الأدوات والعمليات التي يستطيع الوكيل تنفيذها أثناء التجربة.

ويجب أن تكون مراقبة استهلاك API محدودة ببيانات الاستخدام التي يوفرها المزود أو يمكن قياسها أثناء الجلسة، وليس ادعاء الوصول تلقائيًا إلى إجمالي رصيد المستخدم أو استهلاكه خارج المنصة.

---

## 9. نطاق النسخة الأولى (MVP)

تركز النسخة الأولى على تقديم تجربة بسيطة ومستقرة للمستخدم، وتشمل:

1. واجهة رئيسية عربية بهوية أساس.
2. مكتبة وكلاء قابلة للبحث والتصفية.
3. بطاقات تعريفية لكل وكيل.
4. صفحة تفاصيل وتجربة مستقلة لكل وكيل.
5. ربط مفتاح API الخاص بالمستخدم.
6. دعم عدة مزودين للنماذج بحسب التوافق.
7. عرض النماذج المتاحة واختيار النموذج.
8. تشغيل تجربة حية فعلية للوكلاء المنشورين.
9. مراقبة مبسطة لاستهلاك API خلال التجربة.
10. الوصول المباشر إلى مستودعات GitHub.

ولا تشمل النسخة العامة الأولى إنشاء الوكلاء من المستخدمين، أو بناء الوكلاء بصريًا، أو بيع اشتراكات API، أو تقديم أرصدة ذكاء اصطناعي مدفوعة من الشركة.

---

## 10. الهدف النهائي للمشروع

إنشاء منصة رسمية تمثل معرضًا تفاعليًا لوكلاء الذكاء الاصطناعي الذين تطورهم شركة أساس، بحيث يستطيع أي مستخدم استكشاف الوكلاء، وفهم وظائفهم، وتجربتهم فعليًا باستخدام مزود الذكاء الاصطناعي الخاص به، أو الانتقال إلى مستودعاتهم على GitHub.

وتسمح هذه الآلية لشركة أساس بتطوير الوكلاء واختبارهم ونشرهم بشكل مستمر، ثم إدراجهم في المنصة وإتاحتها للجمهور دون الحاجة إلى تعديل بنية الواجهة العامة عند إضافة كل وكيل جديد.

**الخلاصة:**

منصة «وكلاء أساس» ليست منصة لصناعة الوكلاء، بل منصة **لعرض وتجربة وتوثيق ونشر الوصول إلى وكلاء الذكاء الاصطناعي الذين يبنيهم فريق أساس مسبقًا**، مع تجربة مباشرة مرنة تعتمد على مفاتيح API الخاصة بالمستخدمين، وتكامل واضح مع GitHub.
